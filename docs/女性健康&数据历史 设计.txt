三、HTTP 服务
----------------------------------------------------------
框架：aiohttp.web（异步无阻塞）
端口：默认 6789，可配置
监听：0.0.0.0（局域网可访问，含手机）
安全：可选 token（URL 参数 ?k=xxx 或 Cookie）—— 默认关闭，方便本机使用

路由：
GET  /                        → 首页
GET  /calendar                → 生理期日历页
GET  /history                 → 历史数据页
GET  /api/today               → 今日健康快照（含抓取时间戳）
GET  /api/refresh             → 强制刷新拉取小米云端
GET  /api/history?days=7      → 历史数据数组
GET  /api/period              → 生理期数据 + 预测
POST /api/period/mark         → 标记来了 { date: "YYYY-MM-DD" }
POST /api/period/end          → 标记结束 { date: "YYYY-MM-DD" }
POST /api/period/delete       → 删除某条 { start: "YYYY-MM-DD" }
POST /api/period/note         → 备注 { date, note }

启动 / 停止：
- initialize() 时 asyncio.create_task 启动 web
- terminate() 时 gracefully shutdown

----------------------------------------------------------
五、生理期核心逻辑
----------------------------------------------------------

period.json 结构：
{
  "periods": [
    { "start": "2026-09-09", "end": null, "notes": {} },
    { "start": "2026-08-12", "end": "2026-08-17", "notes": {"2026-08-13": "痛经"} }
  ],
  "settings": {
    "avg_cycle_days": 28,     ← 有历史数据后自动计算，初始 28
    "avg_period_days": 5      ← 初始 5
  }
}

预测算法：
- 平均周期 = 最近 3 次周期起始日差值的均值（不够 3 次用默认 28）
- 平均经期 = 最近 3 次周期时长的均值（不够 3 次用默认 5）
- 下次经期预测 = 最近一次 start + avg_cycle_days
- 排卵日 = 下次经期预测 - 14 天
- 排卵期 = 排卵日 前 5 天 ~ 后 4 天

前端渲染：
- 已确认经期 → 实心粉
- 未来预测经期 → 斜纹粉
- 排卵日 → 紫色实心
- 排卵期 → 浅蓝

六、关怀触发（在 monitor.py 增加）
----------------------------------------------------------

新增触发类型：
1. period_incoming  经期预告
   - 触发：距预测起始日 <= 2 天，且今日尚未来
   - 冷却：24 小时一次
   - 时段：中午 12:00 - 22:00
   - 兜底：宝宝, 好像快到日子啦, 包里带片吧~

2. period_care     经期关怀
   - 触发：当前处于经期第 1-5 天
   - 频率：每 2 天一次（不是每天）
   - 时段：13:00 - 22:00（避开早上）
   - 冷却：36 小时
   - 兜底：宝宝, 今天肚子还疼不, 想喝点热的吗?

均遵守 quiet_hours + recent_chat_gap（10 分钟内说过话就不推）
均可单独开关

----------------------------------------------------------
{

  "web_host": "0.0.0.0",           ← 局域网可访问,手机能开
  "web_port": 4847,                ← 你指定

  // === 历史归档 ===

  "history_keep_days": 90,

  // === 生理期基础 ===
  "period_enabled": true,
  "period_default_cycle": 28,
  "period_default_length": 5,

  // === 经期预告关怀（都能改）===
  "period_incoming_care_enabled": true,
  "period_incoming_days_ahead": 2,        ← 提前几天预告
  "period_incoming_cooldown_hours": 24,
  "period_incoming_time_start": "12:00",  ← 允许发送的起始时刻
  "period_incoming_time_end":   "22:00",  ← 允许发送的终止时刻

  // === 经期中关怀（都能改）===
  "period_care_enabled": true,
  "period_care_gap_days": 2,              ← 隔几天关心一次
  "period_care_cooldown_hours": 36,
  "period_care_time_start": "13:00",      ← 允许发送时段
  "period_care_time_end":   "22:00",
  "period_care_days_range": "1-5",        ← 关心经期第几到第几天

  // === 兜底文案（LLM 挂了才用）===
  "fallback_period_incoming": "宝宝, 好像快到日子啦, 包里带片吧~",
  "fallback_period_care":     "宝宝, 今天肚子还疼不, 想喝点热的吗?"
}

【关于文案的机制说明 —— 重要】
- 生理期关怀的文案 不写死。
- 触发时,插件会给 LLM 递一段 hint,例如:
    "她今天是经期第 3 天"
    "距离下次经期预测还有 2 天"
- 然后走跟现在一样的 care_prompt_template(总模板),
  LLM 用你熟悉的口气自己组织语言。
- 所以想改整体语气 → 改 care_prompt_template 那一项就够了,
  不需要为生理期单独写文案。
- fallback_* 只有 LLM 挂了/超时才用。

----------------------------------------------------------
八、安全策略（Token 校验）
----------------------------------------------------------
问题:同一 Wi-Fi 下别人扫到端口就能进,不安全。

方案:
1. web_token_enabled = true 时,所有 /api/* 和页面必须带 token
2. web_token 为空 → 插件启动时自动生成 20 位随机 token,写回配置
3. 访问方式:
   - 首次: http://本机IP:4847/?k=xxxxxxxxxxxxxxxxxxxx
   - 首次访问后,浏览器 Cookie 会记住,之后直接开
     http://本机IP:4847/ 即可
4. 手机浏览器: 首次带 token 打开一次,收藏该 URL,以后直接点收藏
5. 想换 token: 把 web_token 清空重启插件,会重新生成

未通过校验:
- API 返回 401 JSON
- 页面重定向到简短提示页

----------------------------------------------------------
九、生理期关怀的 LLM Hint 生成
----------------------------------------------------------
period_incoming 触发时:
  hint = f"她是我女朋友,好像快来月经了,大概还有 {days} 天"

period_care 触发时:
  hint = f"她是我女朋友,今天是月经期第 {day} 天,想自然地关心她一句"

这两段 hint 会替换到 care_prompt_template 里的 {hint} 占位符,
交给 LLM 生成最终文案。所以最终发出去的话是 LLM 用你的口气生成的,
不会是死板的模板。
